# DGLC / MRR — Diagnosing and Correcting Label-Resident Group Gaps

Code and reproducibility bundle for the paper:

> **When Bias Lives in the Label: Diagnosing and Correcting Label-Resident
> Group Gaps, with a Graduate-Employability Case Study**
> Saleh Abdul Amir Mohammad, Xin Ye, Chen Qian, and Ali A. AL-Bakhrani.
> *IEEE Access*, accepted (manuscript Access-2026-33868); see `CITATION.cff`.

The paper introduces two methods and demonstrates them on a graduate-employability
case study (AMEO 2015), with cross-dataset validation on ACSIncome and a Kaggle
Campus-Recruitment set:

- **Merit-Reward Reversal (MRR)** — a diagnostic that classifies an observed group
  fairness gap as *label-resident* (the target encodes the disparity) versus
  *model-resident* (the estimator introduces it), by testing whether a merit-only,
  group-blind model *favours* the group the label penalises.
- **Decomposition-Guided Label Correction (DGLC)** — a label-side remedy that
  re-targets the outcome toward a non-discriminatory (Neumark) reference structure.
  DGLC is an *internally consistent, tunable normative target* (true by
  construction over the merit weight α); it is not self-certifying.

## Source of truth for all reported numbers

**[`outputs/gap/CANONICAL_NUMBERS.md`](outputs/gap/CANONICAL_NUMBERS.md)** is the
authoritative record of every number quoted in the paper (MRR diagnostic, Oaxaca
decomposition, counterfactual, DGLC regimes, α-frontier, cross-dataset results,
and the label-side head-to-head). If a value in the manuscript, a figure, or a
generated table disagrees with that file, the file wins. It is hand-authored and
is kept in version control (it is *not* regenerated by the run scripts).

## Environment

```bash
python -m pip install -r requirements.txt
```

Pinned versions in `requirements.txt` match the machine on which the canonical
numbers were produced. The **MRR + DGLC gap sub-pipeline** (the paper's core
contribution) needs only the first block of that file. The **full main pipeline**
(deep-learning and tuning stages) additionally needs `torch`, `transformers`,
`optuna`, etc., which are left unpinned and flagged — pin them to your own working
versions before relying on those stages.

> **Interpreter note.** Scripts are invoked as `python`. Some shells ship a
> broken `python3` stub; the gap runner defaults to `python` and honours a
> `PYTHON=` override (`PYTHON=python3.11 bash run_gap.sh`). `run_all.sh` (the
> full main pipeline) is written for a Linux/WSL host with a working `python3`
> and a GPU `torch` build.

## Determinism / reproducibility requirements

The gap sub-pipeline is **bit-for-bit reproducible**. This depends on:

- **`SEED = 42`** everywhere (`config.py`; `PYTHONHASHSEED=42`).
- **`n_jobs = 1`** in every estimator (XGBoost, scikit-learn). Parallel
  backends reorder floating-point reductions and break bit-reproducibility.
- **Single-threaded BLAS / OpenMP**, exported *before* the interpreter starts:
  `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`,
  `NUMEXPR_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS` all = `1`.
- **`PYTHONIOENCODING=utf-8`** so Unicode (e.g. the U+2212 minus) in console
  output does not abort the run on cp1252 (Windows) consoles.

`code/run_gap.sh` sets all of the above for you — prefer it over invoking the
stages by hand.

## How to run

### 1. Obtain the data
The raw datasets are **not** shipped (see "Data & licensing"). Place
`AMEO_2015_train.xlsx` in the repo root; `campus_recruitment.csv` too if you want
the Campus cross-dataset arm. ACSIncome is fetched automatically at runtime by
`folktables` — no manual download.

### 2. Prepare the analysis table
```bash
cd code
python s01_data_prep.py          # writes ../outputs/processed*.parquet + .csv
```

### 3. Run the MRR + DGLC sub-pipeline (the paper's core, fully reproducible)
```bash
cd code
bash run_gap.sh                  # stages 0–10, deterministic; writes ../outputs/gap
```
`run_gap.sh` runs, in order: `gap_common` → `gap01_oaxaca` →
`gap02_ml_counterfactual` → `gap03_fairness_audit` → `gap04_compile` →
`gap05_diagnostic` (MRR) → `gap06_dglc` (DGLC) → `gap07_compile` →
`gap08_cross_dataset` → `gap09_labelside_baseline` → `gap10_partition_sensitivity`.
Compare the results against `outputs/gap/CANONICAL_NUMBERS.md`. `gap10` re-checks
that its P0 arm reproduces the canonical MRR headline and prints a STOP warning
if it does not.

### 4. (Optional) Run the full main pipeline
```bash
cd code
bash run_all.sh                  # stages s01–s18 + compile (needs torch/optuna/etc.)
```
The main pipeline (`s01`–`s18`) covers data prep, EDA/LDA, the System-1 model
panel, deep-learning tabular/text models, System-2 XAI + fairness, recourse,
calibration, ablation, tuning, and the reviewer/sensitivity analyses. Its
figures and tables feed the case-study sections of the paper; the **MRR/DGLC
contribution lives entirely in the `gap*` sub-pipeline** above.

The **aggregate metrics behind the paper's model-panel and audit tables**
(17-model panel with AUROC/CI/F1/MCC, tuned-vs-default, feature-group ablation,
calibration, label-threshold sensitivity, fairness and threshold tables) are
committed under `outputs/metrics/` and `outputs/tables/` so every reported
number can be checked without re-running the pipeline; `run_all.sh` regenerates
them at the same paths.

Note: `outputs/tables/label_sensitivity.csv` is the original-run file with the
older column layout (`label, pos_rate, tree_AUROC, tree_CI, deep_AUROC,
deep_CI, tree_beats_deep, EO_gap`); a fresh `run_all.sh` writes the current
layout (`label, pos_rate, best_tree, tree_AUROC, best_deep, deep_AUROC,
AUROC_diff, EO_gap`).

## Data & licensing

The raw datasets have **different redistribution terms** and are therefore not
committed to this repository. Obtain each from its source:

| Dataset | File | Source / how to obtain | Redistribution |
|---|---|---|---|
| **AMEO 2015** (Aspiring Minds Employability Outcomes) | `AMEO_2015_train.xlsx` | Aspiring Minds / public mirrors of the AMEO research release | Terms unclear — **do not redistribute**; document source and have users download it. |
| **ACSIncome** | *(none — fetched at runtime)* | `folktables` (US Census ACS PUMS; public domain) | Fetched programmatically; nothing to ship. |
| **Kaggle Campus Recruitment** | `campus_recruitment.csv` | Kaggle "Campus Recruitment" dataset page | Kaggle per-dataset terms — **do not redistribute**; users download from Kaggle. |

Derived files (`outputs/processed*.{csv,parquet}`) inherit the source data's
terms and are git-ignored for the same reason.

> **Policy:** this repository ships **no** raw or individual-level derived data
> (enforced by `.gitignore`); each dataset is obtained from its original source
> as documented above. Only code, configuration, fixed seeds, and aggregate
> outputs (summary tables, metrics, figures) are published.
